# 기획: 농가 다중 계정 연결 + 관리자 권한 분리

작성 목적: 구현·검수에 넘길 **제품 기획서**.  
기준 데이터: **라이브 DB `farmassi`** (2026-11-22 조회). 스키마 추측용 마이그레이션/문서 덤프가 아니라 라이브 상태를 우선한다.

---

## 1. 배경 / 문제

### 1.1 계정 연결이 1명뿐임

- 관리자 농가 화면의 「계정 연결」(담당 계정 피커)은 **한 농가에 계정 1명만** 연결할 수 있다.
- UI는 선택된 계정 칩 1개 + 「해제」 형태다.  
  예: `김마원 · 01053166690` + 해제
- 운영상 **한 농가에 여러 관리 계정을 붙이고 싶다.**

### 1.2 admin이면 플랫폼·전 농가에 다 들어감

- 현재 `profiles.role = 'admin'` 이면:
  - 플랫폼 관리 페이지(`/admin`, `/admin/farms` 목록, 전체 주문·입금·송장 등) 접근 가능
  - **연결 여부와 무관하게** 모든 농가의 `/admin/farms/:farmId/...` 접근 가능
- 그래서 “이 농가 운영만 시킬 사람”을 admin으로 두면, **내가 쓰는 기본 admin 전체**와 **다른 농가 admin**까지 열려 버린다.

### 1.3 원하는 방향 (한 줄)

> **슈퍼어드민만** 지금처럼 전체 admin + 모든 농가를 쓰고,  
> **추가 연결 계정**은 **그 농가 admin 페이지만** 쓰게 한다.  
> 동시에 **한 농가에 여러 admin**을 붙일 수 있게 한다.

---

## 2. 목표 (Must)

1. 농가당 **여러 계정 연결** (추가·개별 해제).
2. 역할 분리:
   - **슈퍼어드민**: 플랫폼 admin 전체 + 모든 농가 관리 페이지
   - **일반 어드민**: **연결된 농가 1곳**의 관리 페이지만
3. 슈퍼어드민·일반 어드민 **모두** 고객(스토어/주문 등 customer) 기능을 **같이** 쓸 수 있어야 한다. (역할이 서로 배타적이면 안 됨)
4. **한 농가 → 여러 일반/슈퍼 어드민** 가능.
5. **일반 어드민 → 농가 권한은 최대 1곳**만.

---

## 3. 비목표 (이번 기획에서 하지 않음)

- 농가 멤버 `staff` vs `owner`의 세부 기능 차이 재설계 (필요 시 후속).
- 고객 전용 UI/결제 플로우 개편.
- 슈퍼어드민을 UI에서 마음대로 승격/강등하는 운영 콘솔 (초기에는 DB/운영 스크립트로 지정해도 됨. 필요하면 후속).

---

## 4. 용어

| 용어 | 의미 |
|------|------|
| **플랫폼 admin / 기본 admin 페이지** | `/admin`, `/admin/farms`(목록), `/admin/orders`, `/admin/customers`, `/admin/deposits`, 송장·입금원장 등 **전역** 관리 화면 |
| **농가 admin 페이지** | `/admin/farms/:farmId` 및 하위 (대시보드, 상품, 주문, 고객, 입금, 배송, 설정 등) |
| **슈퍼어드민** | 플랫폼 admin + **모든** 농가 admin 접근 |
| **일반 어드민** | **계정 연결된 그 농가 1곳**의 농가 admin만 접근. 플랫폼 admin·다른 농가 불가 |
| **계정 연결** | 특정 카카오 로그인 프로필을 특정 농가의 관리자로 묶는 것 (`farm_members` 등) |
| **customer 권한** | 일반 구매자처럼 랜딩/스토어/주문/마이주문 등을 쓰는 것 |

## 5. 라이브 현황 (기획 기준 스냅샷)

조회 시점 라이브 `farmassi`:

### 5.1 역할 값

- `profiles.role` 허용값: **`customer` | `admin`만** (슈퍼 구분 없음)
- 체크: `role IN ('customer', 'admin')`

### 5.2 현재 admin 3명 → **전원 슈퍼어드민으로 취급·이관**

| 이름 | 연락처 | 현재 role | 연결 농가 (farm_members) |
|------|--------|-----------|---------------------------|
| 박지훈 | 010-8767-5708 | admin | 가평운악산포도과즙음료영농조합법인, 시골농원, 주영농원, 진영농원, 탁이네 포도원 (5) |
| 김이현 | 010-5109-0625 | admin | 안당농장 (1) |
| 김미자 | 010-2075-5708 | admin | **없음 (0)** |

기획 결정: 위 3명은 모두 **슈퍼어드민**.  
→ 김미자도 연결 농가가 없어도 **플랫폼 admin + 모든 농가** 접근 가능해야 한다.

### 5.3 농가·멤버

- 농가 6곳, `farm_members`는 농가당 **owner 1명**만 존재 (다중 연결 없음).
- `farm_members.member_role` 허용: `owner` | `staff` (라이브 CHECK).

### 5.4 현재 동작의 문제 (라이브 admin 기준)

- 김이현은 안당농장만 연결돼 있어도, role=admin 이라 **다른 농가·플랫폼 전체**에 들어갈 수 있다.
- “추가 연결만 한 일반 운영자”를 만들 방법이 없다.

## 6. 역할·권한 매트릭스 (확정)

### 6.1 역할 종류

| 역할 | 설명 |
|------|------|
| `customer` | 구매자 |
| `admin` | **일반 어드민** (농가 스코프) |
| `super_admin` | **슈퍼어드민** (플랫폼 + 전 농가) |

> 구현 시 컬럼/플래그 형태는 개발자가 정하되, **아래 행위 정의는 반드시 충족**.

### 6.2 접근 권한

| 행위 | customer | 일반 admin | 슈퍼어드민 |
|------|----------|------------|-------------|
| 스토어/주문/마이페이지 등 고객 기능 | O | **O (동시 가능)** | **O (동시 가능)** |
| 플랫폼 `/admin/*` (목록·전역 주문·입금 등) | X | **X** | **O** |
| 본인이 **연결된** 농가 `/admin/farms/:id/*` | X (연결 없으면) | **O (그 1곳만)** | **O** |
| **연결되지 않은** 다른 농가 `/admin/farms/:다른id/*` | X | **X** | **O** |
| 농가에 계정 연결/해제 (운영 UI) | X | X (기본) | **O** |
| 농가 신규 생성 등 플랫폼 농가 관리 | X | X | **O** |

### 6.3 “customer와 복수로”

- 슈퍼어드민·일반 어드민 **모두** 고객 기능을 막으면 안 된다.
- “admin이면 주문 못 함 / customer로만 로그인해야 함” 같은 배타 구조 금지.
- 한 카카오 계정으로 **구매도 하고 농가(또는 플랫폼) 관리도** 할 수 있어야 한다.

### 6.4 농가 ↔ 계정 관계

| 규칙 | 내용 |
|------|------|
| 농가 1곳 : 계정 N명 | **허용** (다중 어드민) |
| 일반 admin 1명 : 농가 | **최대 1곳**만 연결·접근 |
| 슈퍼어드민 : 농가 | 멤버 행 유무와 관계없이 **모든 농가** 접근. (멤버로 여러 농가에 있어도 됨) |
| 기존 admin 3명 | 데이터 이관 시 전부 `super_admin` |

### 6.5 일반 admin이 농가 0곳이면

- 플랫폼 admin 진입 **불가**.
- 농가 페이지도 갈 곳 없음 → **접근 거부** 또는 안내 후 고객 홈/로그인 쪽으로.  
  (슈퍼가 아닌데 연결도 없으면 관리자로 쓰지 않는 상태)

## 7. 사용자 시나리오

### 7.1 슈퍼어드민 (예: 박지훈)

1. `/admin/login` 등으로 로그인.
2. `/admin` 대시보드, 농가 목록, 전역 주문/입금 등 **기존과 동일**하게 사용.
3. 임의의 `/admin/farms/:farmId/...` 진입 가능.
4. 동시에 고객용 농가 스토어에서 주문 가능.

### 7.2 슈퍼가 농가에 계정 여러 개 연결

1. 플랫폼 농가 관리에서 해당 농가 「계정 연결」.
2. 검색(이름/연락처/계정 ID)으로 프로필 선택 → **목록에 추가** (기존 1명 칩을 교체하는 방식이 아님).
3. 이미 연결된 계정은 칩/리스트로 여러 명 표시, 각자 「해제」.
4. 새로 연결된 계정이 아직 customer면 → **일반 admin**으로 올리고 해당 농가 멤버로 등록.
5. 이미 슈퍼어드민이면 role은 슈퍼 유지, 멤버로만 추가해도 되고 안 해도 됨 (슈퍼는 멤버 없이도 전 농가 접근). 다만 UI에서 “연결”하면 멤버로 남겨 누가 담당인지 보이게 하는 것을 권장.
6. 대상이 **이미 다른 농가에 일반 admin으로 연결**돼 있으면 → **연결 거부** + 사유 표시 (“이미 ○○농가에만 연결 가능”).

### 7.3 일반 어드민 (추가 연결 계정)

1. 카카오 로그인 후 관리 화면 진입 시도.
2. 플랫폼 `/admin`, `/admin/farms` 목록, 전역 주문 등 → **불가** (리다이렉트 또는 403/안내).
3. 자동으로 **본인 연결 농가** `/admin/farms/{연결농가Id}` 로 보냄.
4. URL을 조작해 다른 농가 ID로 들어가도 → **차단**, 자기 농가로 되돌리거나 거부.
5. 고객 스토어/주문은 정상 사용.

### 7.4 해제

1. 슈퍼가 농가에서 특정 계정 「해제」.
2. 해당 농가 멤버십 제거.
3. 그 계정이 더 이상 어느 농가에도 없고 슈퍼도 아니면 → 일반 admin 권한으로 관리 페이지 진입 불가 (customer로 강등할지, admin 유지한 채 농가만 없는지로 구현 선택 가능하나, **관리 UI 진입은 불가**가 제품 요구).  
   권장: 연결 농가가 0이 된 일반 admin은 `customer`로 되돌리거나, role은 두되 가드에서 막기. **검수 시 한 가지로 고정**할 것.

## 8. UI 요구 (계정 연결)

대상: 관리자 농가 생성/편집·「계정 연결」에 쓰는 담당 계정 피커  
(현재 단일 선택 칩 UI가 있는 곳).

### 8.1 Must

- 여러 계정을 **동시에** 연결 상태로 보여 준다.
- 검색 후 클릭 시 **교체가 아니라 추가**.
- 이미 선택된 계정은 다시 눌러도 중복 추가하지 않음.
- 각 연결 계정마다 「해제」.
- 라벨은 기존처럼 `이름 · 연락처` 형태 유지 가능.
- 슈퍼만 이 연결 UI를 쓴다 (플랫폼 농가 관리 맥락).

### 8.2 대표 담당 (`owner_user_id`)

- DB에 농가당 대표 owner FK가 있다면 **대표 1명** 개념은 유지해도 된다.
- **실제 접근 권한의 근거는 “연결 목록(멤버)”** 이다. 대표만 있고 멤버에 없으면 일반 admin 접근이 되면 안 된다 (또는 대표 변경 시 멤버와 항상 동기화 — 구현 시 하나로 통일).
- 기획 권장:  
  - 다중 권한 = 멤버 테이블  
  - `owner_user_id` = 대표 표시/레거시 호환용 (첫 연결자 또는 슈퍼가 지정)

## 9. 라우팅·가드 요구

### 9.1 플랫폼 라우트 (슈퍼만)

예시 (현재 앱 기준, 동일 성격 전부 전부):

- `/admin`
- `/admin/farms` (목록)
- `/admin/orders`, `/admin/customers`
- `/admin/deposits`, `/admin/deposits/ledger`
- `/admin/shipments` 및 송장 수동/이력 등 전역 화면

→ **슈퍼어드민만**. 일반 admin이 직접 URL 쳐도 진입 불가.

### 9.2 농가 워크스페이스

- `/admin/farms/:farmId/*`
  - 슈퍼: 항상 허용
  - 일반 admin: `farmId`가 **본인 연결 농가**일 때만 허용
  - 그 외: 거부

### 9.3 로그인 후 랜딩

- 슈퍼 → 기존처럼 `/admin` (또는 쓰던 기본 admin 홈)
- 일반 admin → `/admin/farms/{유일 연결 농가 id}`
- 연결 없는 일반 admin → 관리 영역 진입 불가 + 안내

### 9.4 네비게이션

- 슈퍼: 기존 플랫폼 admin 네비 유지.
- 일반 admin: 플랫폼 네비(전체 농가·전역 주문 등) **노출 금지**. 해당 농가 워크스페이스 네비만.

## 10. 서버·데이터 권한 요구 (프론트만 막으면 안 됨)

- URL 가드만으로 끝내면 안 된다. API·DB 정책도 동일 규칙을 따른다.
- **전역** 작업 (예: 전체 입금 스크랩, 전 농가 목록 관리성 쓰기, 타 농가 데이터 조회) → **슈퍼만**.
- **농가 단위** 읽기/쓰기 → 슈퍼 **또는** 해당 농가 멤버(일반 admin).
- 일반 admin이 role 문자열만 `admin`이라는 이유로 전역 우회되면 **버그**.

---

## 11. 데이터 이관 (런칭 시)

1. 역할에 `super_admin` (또는 동등 구분) 추가.
2. 라이브 기준 아래 3명을 **슈퍼어드민**으로 승격:
   - 박지훈 (`010-8767-5708`)
   - 김이현 (`010-5109-0625`)
   - 김미자 (`010-2075-5708`)
3. 기존 농가 `farm_members` / `owner_user_id`는 깨지지 않게 유지.
4. 이후 「추가 연결」되는 계정만 일반 `admin` + 해당 농가 멤버.

---

## 12. 검수 체크리스트

- [ ] 한 농가에 계정 2명 이상 연결·화면 표시·각자 해제 가능
- [ ] 일반 admin A가 농가1 연결 시, 농가2에는 연결 거부
- [ ] 일반 admin은 `/admin` 등 플랫폼 진입 불가
- [ ] 일반 admin은 연결 농가 페이지만 가능, 다른 농가 URL 직접 입력 시 차단
- [ ] 슈퍼 3명(이관 후)은 플랫폼 + 모든 농가 가능 (김미자·농가 멤버 0이어도 가능)
- [ ] 슈퍼·일반 admin 모두 고객 스토어/주문 가능
- [ ] API로 타 농가/전역 자원 요청 시 일반 admin 거부
- [ ] 연결 해제 후 해당 일반 admin의 그 농가 접근 불가

---

## 13. 기획 결정 로그 (이 문서에 반영된 합의)

1. 계정 연결 **다중** 지원.
2. 슈퍼 제외 시, admin 접속은 **계정 연결된 농가 페이지만** (플랫폼 admin·타 농가 제외).
3. 현행 admin 3명 = **전원 슈퍼어드민**.
4. 추가 연결 계정 = **일반 어드민**, **농가 1곳만**.
5. 슈퍼·일반 모두 **customer 기능과 복수(동시)** 가능.
6. 한 농가에 **여러 어드민** 가능.

## 15. 열려 있지 않은 것 / 구현자가 고르면 되는 것

아래는 제품 방향이 아니라 **구현 선택**이다. 다만 검수 전에 팀에 한 줄로 박아 두면 좋다.

- `profiles.role`을 `super_admin` 문자열로 확장할지, 별도 플래그/roles 배열로 할지
- 일반 admin 연결 해제 시 role을 `customer`로 되돌릴지
- `owner_user_id`와 `farm_members` 동기화 규칙의
- 슈퍼 승격/강등 UI를 당장 넣을지 (없어도 이관 스크립트로 충분하면 OK)

**제품으로 이미 닫힌 것**은 6·7·8·9·11절이다. 위 선택 때문에 그 절을 약화하면 안 된다.
